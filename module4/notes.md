# Module 4: Git and GitHub Workflow

## What I Learned

- Git is a version control system that tracks changes to files over time.
- A repository stores the full history of a project.
- `git add` stages changes; `git commit` saves a snapshot with a message.
- `git push` sends commits to GitHub so they are backed up and shareable.
- Branches let you work on changes without affecting the main codebase.
- A pull request is how you propose merging a branch back into main.
- Reviewing the "Files changed" tab before merging is good practice.

## Commands Used
- `git status` — see what has changed
- `git add <file>` — stage a file
- `git commit -m "message"` — commit with a message
- `git push` — push to GitHub
- `git checkout -b <branch>` — create and switch to a new branch
- `git pull` — bring remote changes down locally
